# TetherRescue — AirwayTow (끌고 오기) v0.2

MuJoCo 가짜 바다에서 구조 로봇이 줄로 사람을 끌고 오는 시뮬레이션입니다.
기획서 v3.1의 ② **AirwayTow** 단계 첫 버전: 파도·부력·물 저항, 줄(당김·끊김), 얼굴 잠김 판정, PID 속도 조종, 성적 매기기.

v0.2: **전체 구조 임무(두 단계 유도)** 와 **ROS2 / rviz2 좌표 찍기** 추가 → 아래 [전체 구조 임무](#전체-구조-임무-두-단계-유도) 참고.

## 다른 PC(집 등)에서 처음 실행하기 (Windows)

1. 준비물 설치 (한 번만, PowerShell에서):
   ```powershell
   winget install Git.Git
   winget install Python.Python.3.12
   ```
2. 내려받기: 원하는 폴더에서 (경로는 영어로만 된 곳을 권장, 예: `D:\Projects`)
   ```powershell
   git clone <이 저장소 주소>
   ```
3. 받은 폴더의 **`setup_windows.bat`** 실행 → 가상환경·패키지·MuJoCo 확인까지 자동 (필요하면 Visual C++ 재배포 패키지도 설치)
4. **`view_simulation.bat`** 실행

작업 내용 맞추기: 작업을 끝낸 PC에서 `git add -A` → `git commit -m "설명"` → `git push`,
다른 PC에서 시작하기 전에 `git pull`. (`.venv`, `results/` 는 올리지 않습니다 — PC마다 따로 생김)

## 설치 (직접 하기, Windows, Python 3.12)

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

> `mujoco.dll ... Could not find module` 에러가 나면 **Microsoft Visual C++ 재배포 패키지(x64)** 를 설치하세요.
> `winget install Microsoft.VCRedist.2015+.x64`

## 실행

**가장 쉬운 방법**: 프로젝트 폴더의 `view_simulation.bat` 을 더블클릭하면 창 두 개가 나란히 뜹니다.
VS Code 터미널(PowerShell)에서는 `.\view_simulation.bat` 으로 실행합니다.

**왼쪽 — 실험 설정 패널** (슬라이더를 끌거나 숫자를 입력)

| 묶음 | 값 | 반영 시점 |
| --- | --- | --- |
| 끌고 오기 | 목표 속도, 출발 가속 시간, 최대 추진력, 구조 거리 | 바로 |
| 바다 · 줄 · 사람 | 파도 높이(1초에 걸쳐 부드럽게), 줄 끊어지는 힘, 줄 탄성, 줄 길이, 선수파 계수 | 바로 |
| PID 계수 | 속도 Kp·Ki, 방향 Kp·Kd | 바로 |
| 다시 시작할 때 적용 | 파도 주기, 파도 방향, 시드 | **[적용하고 다시 시작]** 버튼 |

- 버튼: 일시정지 / 적용하고 다시 시작 / 기본값 복원(설정 파일 값으로)
- 보기: 재생 속도, 카메라, 자동 재시작, 그래프 켜기·끄기
- 실험 결과: 판이 끝날 때마다(성공·실패 모두) **회차별로 자동 기록**됩니다 → `results/실험기록.csv`
  - 한글 열 이름, 엑셀에서 바로 열림. 프로그램을 껐다 켜도 회차 번호가 이어지고 지난 기록도 표에 보입니다.
  - 표: 성공 = 초록 줄, 실패 = 빨간 줄. 위에 전체 횟수·성공률 요약. [기록 파일 열기] 로 엑셀에서 열기.
  - 파일이 엑셀에서 열려 있어 못 쓰면 기억해 뒀다가 다음 판 때 같이 씁니다.
  (`changed_mid_run=1` 은 그 판 도중에 값을 바꿨다는 뜻)
- 마우스를 값 이름 위에 올리면 설명이 뜹니다.

**오른쪽 — 3D 뷰어**: 왼쪽 위 = 현재 상태, 오른쪽 = 실시간 그래프(속도 / 줄 힘 / 입 높이, 최근 15초), 왼쪽 아래 = 단축키 안내.
글자·그래프는 모두 한글입니다 (MuJoCo 기본 글꼴은 한글이 안 돼서 맑은 고딕으로 그린 그림을 얹음).
한 판이 끝나면 결과가 위에 뜨고 3초 뒤 다음 시드로 다시 시작합니다. 둘 중 한 창을 닫으면 종료됩니다.
패널 없이 뷰어만: `.\view_simulation.bat --no-panel` / 끌고 오기만으로 시작: `.\view_simulation.bat --mode tow`
(모드는 패널 [구조 임무 · 지도] 탭에서도 바꿀 수 있고, [적용하고 다시 시작] 때 반영됩니다)

| 단축키 | 기능 |
| --- | --- |
| Space | 일시정지 / 계속 |
| Backspace | 처음부터 다시 (같은 시드) |
| ↑ / ↓ | 목표 속도 +0.1 / −0.1 m/s (바로 반영) |
| = / - | 빠르게 / 느리게 (최대 4배 빠르게 ~ 8배 느리게) |
| 6 / 7 / 8 | 카메라: 사람 따라가기 / 로봇 따라가기 / 위에서 보기 |
| 9 | 그래프 켜기 / 끄기 |
| 마우스 | 왼쪽 드래그 = 회전, 오른쪽 드래그 = 이동, 휠 = 확대·축소 |

MuJoCo 뷰어 기본 단축키 중 쓸 만한 것: `1` 물 표면 숨기기/보이기, `T` 반투명, `W` 와이어프레임, `S` 그림자, `Tab` 설정 패널, `F1` 전체 도움말.
(알파벳 키는 대부분 뷰어가 화면 효과 켜기/끄기로 쓰고 있어서 제 단축키는 숫자·특수키로만 정했습니다.)

```powershell
# 한 판 실행 → results/run_tow/ 에 CSV 기록·그래프·점수 JSON
.venv\Scripts\python scripts\run_tow.py --speed 1.2 --wave 1.0 --seed 0

# 목표 속도별 비교 (시드 3개 평균) → results/sweep_speed/
.venv\Scripts\python scripts\sweep_speed.py --wave 1.0

# 3D 화면으로 보기 (줄 색: 노랑=느슨, 주황→빨강=팽팽, 회색=끊어짐)
.venv\Scripts\python scripts\view_tow.py --speed 1.2 --wave 1.0

# 물리 검사
.venv\Scripts\python -m pytest -q
```

## 전체 구조 임무 (두 단계 유도)

"사람이 지도에 좌표를 찍어 주고 → 로봇이 그쪽으로 가고 → 가까이서 직접 감지"하는 흐름입니다.
`view_simulation.bat` 을 실행하면 이 모드로 시작합니다 (패널의 [구조 임무 · 지도] 탭).

```
좌표 기다림 ──(지도 클릭 / rviz2 2D Goal Pose / 자동 신고)──▶ ① 멀리서: GPS 웨이포인트 주행
   ──(열화상·소나가 사람을 '확인')──▶ ② 가까이서: 직접 감지로 마무리 접근 ──(사람 앞 1.6 m에 멈춤)──▶
   ③ 튜브 건네기: 뱃머리 앞 물 위로 튜브를 내밂 ──(손 닿는 곳 0.7 m 안, 0.8초)──▶ 사람이 팔을 뻗어 잡음(1.2초)
   ──▶ 겨드랑이 아래에 끼움(3초) = 줄 연결 ──▶ 기지로 견인 (기존 PID 견인) ──▶ 사람이 기지 5 m 안 = 구조 성공
   (손이 안 닿으면 1.15 m까지 조금씩 다가감, 15초 안에 못 잡으면 추정이 틀린 것으로 보고 다시 탐색)
   (좌표에 도착했는데 못 찾으면 사각 나선 탐색, 90초 안에 못 찾으면 실패)
```

| 구분 | 무엇을 쓰나 | 정확도 / 특징 (설정에서 바꿈) |
| --- | --- | --- |
| 멀리서 | 목표 좌표 + 로봇 GPS | GPS 오차 2.5 m (천천히 흘러가는 오차). 도착 판정 4 m |
| 가까이서 | 가상 **열화상** (뱃머리) | 20 m, 시야 60°, **방향만** 앎. 머리가 물에 잠기면 안 보임. 멀고 파도 높을수록 놓침 |
| 가까이서 | 가상 **소나** (물속) | 25 m, 시야 120°, 거리+방향. 머리가 잠겨도 보임. 파도 높을수록 **가짜 탐지** 많음 |
| 판단 | 추적기 | 소나 3번 겹치면, 또는 열화상·소나 방향이 맞으면 '확인'. 목격 지점에서 먼 탐지는 무시 |

- 근거리 센서는 **로봇 기준 상대 위치**를 주므로 GPS 오차와 상관없이 정확히 다가갈 수 있습니다 (두 단계 유도의 핵심).
- 지도: 빨간 점선 원 = 목격 지점(신고 오차), ✕ = 목표 좌표, 노란 원 = 로봇이 생각하는 자기 위치(GPS), 초록 원 = 감지로 찾은 사람.
  "실제 익수자 위치 보기"를 켜면 정답이 보입니다. "자동 신고"를 켜면 클릭 없이 목격 지점으로 출발합니다.
- 결과 표의 비고: 감지까지 / 줄 연결까지 걸린 시간, 목표 좌표 오차.
- 첫 결과 (목격 지점을 목표로, 시드 0~5): 파고 0 / 1 / 1.5 m 모두 6판 성공. 감지 6~13초, 줄 연결 21~34초 (파고 1.5 m의 한 판은 잘못된 감지 때문에 92초).
- 튜브 건네기로 바꾼 뒤 (같은 조건): 18판 모두 성공. 줄 연결 29~67초, 최대 줄 힘 168 N.
  연결 순간 줄이 3 m보다 멀면 그만큼 풀어 둔 채 연결하고 0.2 m/s로 감아 들입니다 (확 당겨져 끊어지는 것 방지).
- '손이 닿는가'는 시뮬레이터가 실제 어깨 위치로 판정합니다. 로봇 두뇌는 사람이 잡았다는 것만 압니다.

### ROS2 / rviz2 에서 좌표 찍기

```
[Windows] 시뮬레이션 ──상태(UDP 1초 10번)──▶ [WSL Ubuntu 24.04] ROS2 브리지 ──▶ rviz2 지도
                     ◀──목표 좌표───────────                   ◀── "2D Goal Pose" 클릭
```

1. `view_simulation.bat` 실행 → 패널 [구조 임무 · 지도] 탭에서 **ROS2 연결 (rviz2)** 체크
2. `ros_bridge_wsl.bat` 실행 (WSL에서 브리지 + rviz2가 같이 뜸)
3. rviz2 위쪽 **2D Goal Pose** 를 누르고 바다를 클릭 → 로봇 출발. (Publish Point 도구로 찍어도 됨)
   패널에 "브리지 연결됨"이 뜨면 정상입니다.

| 토픽 | 방향 | 내용 |
| --- | --- | --- |
| `/goal_pose` (geometry_msgs/PoseStamped) | rviz2 → 시뮬 | 목표 좌표 (2D Goal Pose) |
| `/clicked_point` (geometry_msgs/PointStamped) | rviz2 → 시뮬 | 목표 좌표 (Publish Point) |
| `/tether_rescue/markers` (visualization_msgs/MarkerArray) | 시뮬 → rviz2 | 로봇·익수자·기지·목표·센서 시야·탐지·탐색 경로 |
| `/tether_rescue/robot_pose` (geometry_msgs/PoseStamped), TF `map→base_link` | 시뮬 → ROS2 | 로봇 위치 |
| `/tether_rescue/state` (std_msgs/String) | 시뮬 → ROS2 | 상태 JSON (녹화·디버그용) |

- 좌표계는 `map` (x = 동쪽/앞, y = 북쪽, m). 시뮬레이터 월드 좌표와 같습니다.
- 시뮬레이터가 **먼저 보내고 브리지가 답장**하는 방식이라 Windows 방화벽 설정 없이 WSL과 통신됩니다.
  WSL 주소는 자동으로 찾습니다 (`config/tow_default.yaml` 의 `ros_bridge`).
- 브리지가 꺼져 있거나 느려도 시뮬레이션 결과는 바뀌지 않습니다.
- 이 PC의 WSL에는 ROS2 Jazzy가 이미 있습니다. 다른 PC는 Ubuntu 24.04 + `ros-jazzy-desktop` 이 필요합니다 (브리지는 mujoco 불필요).

> ⚠ 기획서 4.3은 "ROS2는 보기·기록만"으로 정했습니다. 목표 좌표 입력은 **로봇을 직접 조종하는 게 아니라
> 구조요원이 위치를 알려 주는 입력**이라 예외로 넣었지만, 팀 회의에서 확인이 필요합니다. (ROS2 양식 담당: ②)

## 모델 요약

- **부력**: 몸을 블록으로 나눠 잠긴 블록만큼 위로 밉니다 → 기울면 다시 섭니다.
- **물 저항**: 블록마다 물에 대한 상대 속도로 선형+2차 저항. 파도의 물 입자 속도 포함.
- **줄**: `T = k·(늘어난 길이) + c·(늘어나는 속도)`, `T ≥ 0`. 294N(≈30kg)을 0.05초 넘게 넘으면 끊어짐.
- **얼굴 잠김**: 입 높이 < 물 높이 + 선수파 상승(`bow_wave_coef · v²/2g`) 이면 잠김.
  선수파 계수는 "빨리 끌면 머리 앞에 물이 쌓인다"는 효과를 단순화한 **임시값**이라 검증이 필요합니다.
- **엔진**: 선미 아래에서 밀고, 조향각만큼 밀 방향을 꺾음. 반응 지연 0.4초.
- **뒤집힘**: 60° 넘게 기울면 실패.
- **겉모양**: 로봇은 작은 구조정(뾰족한 뱃머리, 선외기, 견인 기둥, 뱃머리 열화상 카메라), 줄 끝에는 주황·흰 줄무늬 구명튜브.
  구조 임무에서는 출발할 때 튜브가 갑판에 실려 있다가, 건네기 단계에서 뱃머리 앞 물 위로 나가고,
  사람이 팔을 뻗어 잡아 가슴으로 끌어와 끼우면 줄이 연결됩니다. 견인 중에는 팔을 튜브 위로 걸칩니다.
  사람은 가슴·골반·다리·발·목·팔(위팔·아래팔·손)이 있고, 평소에는 팔을 벌려 천천히 젓습니다.
  보이는 부품은 질량 0·충돌 없음이라 **물리(부력·저항·충돌)는 여전히 상자 모양**으로 계산합니다
  (사람 = 다리 포함 길이의 몸통 상자 + 머리 공).
  줄 힘도 지금처럼 선미 견인점 ↔ 가슴 견인점 사이로 계산하고, 화면의 줄만 견인 기둥 ↔ 튜브로 그립니다.
- **기록(50Hz)**: 앞 6개 `tension, acc_x, acc_y, acc_z, throttle, rudder` 는 ⑤ TetherSense 입력 후보입니다.
