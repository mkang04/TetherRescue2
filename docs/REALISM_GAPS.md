# Realism Gaps

이 시뮬레이션에서 **현실과 차이가 나는 부분**과, 그런 환경을 만들 때 생기는 **MuJoCo의 한계**를 정리한 문서입니다.
(2026-11-09 기준 코드, MuJoCo 3.17. ✅ = 이후 구현함)

---

## 요약

- 로봇의 몸 움직임과 충돌은 **MuJoCo가 정확하게** 계산합니다.
- **물(부력·저항·파도)** 은 MuJoCo가 계산하지 않기 때문에 Python 근사식으로 대신합니다. 현실과의 차이는 대부분 여기서 생깁니다.
- 영향이 큰 순서는 물의 힘 → 파도 → 추진기 → 사람 → 줄 → 센서입니다.

## 1. 현실 구현도가 떨어지는 부분

### ① 물의 힘 — [`hydro.py`](../tether_rescue/ocean/hydro.py)

| 현재 | 현실과의 차이 |
| --- | --- |
| 몸을 블록으로 나눠, 잠긴 부피만큼 부력을 줌 | 기본 방식은 맞음. 다만 파도가 물체를 미는 힘, 물체에 부딪혀 꺾이는 힘(회절·방사)은 없음 |
| ✅ ~~부가질량(added mass) 없음~~ → [`added_mass.py`](../tether_rescue/ocean/added_mass.py)로 구현 | 물속 물체가 가속하려면 주변 물까지 같이 밀어야 함. 이 효과가 없어서 배와 사람이 실제보다 쉽게 가속하고 멈춤. 견인 시작 순간의 줄 힘이 실제보다 작게 나올 가능성이 큼 |
| 저항 = 선형 + 2차, 계수는 임의값 | 실제 선체 저항 곡선(조파저항 등)이나 실험값이 아님 |
| 배가 물을 밀어도 물은 그대로 | 배가 만드는 물결·항적, 사람 뒤 와류가 없음. 배와 사람이 물을 통해 서로 영향을 주지 않음 |

### ② 파도 — [`waves.py`](../tether_rescue/ocean/waves.py)

- 사인파 8개를 겹친 **선형 파도**, 깊은 바다 가정
- 부서지는 파도, 뾰족한 파도 꼭대기, 바람 없음
- 해류는 어디서나 같은 상수

### ③ 추진기 — [`scene.py`](../tether_rescue/scene.py) `thrust` / `steer` 구동기

- ✅ ~~프로펠러가 물 밖에 나와도 추력이 그대로 나옴~~ → 드러난 만큼 추력 감소
- ✅ ~~배 속도가 올라가도 추력이 줄지 않음~~ → `T = T0·(1 − u/5 m/s)`
- 배터리·전류·모터 과열 같은 전력 제한 없음
- 선외기 물속 부분의 물 저항 없음 (조향 서보가 물의 힘을 받지 않고 돌아감)
- 선외기 질량 3 kg, 조향 반응 0.1 s, 조향 강성 40은 **가정값** (실제 제품 값 아님)

### ④ 사람

- 몸통 상자 1개 + 머리 공 1개 + 목 관절 1개. 팔다리는 겉모양뿐이고 물리 계산에 없음
- 허우적거림, 의식 저하, 가라앉는 정도의 개인차 없음

### ⑤ 줄 — [`tether.py`](../tether_rescue/tow/tether.py)

- **질량 없는 직선 고무줄**. 처짐, 물에 뜨거나 끌리는 효과, 감김·걸림 없음
- 느슨했다가 팽팽해지는 순간의 충격이 실제보다 단순함

### ⑥ 센서 — [`sensors.py`](../tether_rescue/mission/sensors.py), [`gps.py`](../tether_rescue/mission/gps.py)

- ✅ 소나: MuJoCo 광선(`mj_ray`)으로 실제 빔을 쏨. ✅ 열화상: 카메라 ~ 머리 사이를 파도가 가리는지 계산

- ✅ ~~IMU에 잡음 없음~~ → MPU-6050 데이터시트 잡음 밀도로 추가
- GPS 오차는 천천히 흘러가는 오차(1차 가우스-마르코프)로 비교적 현실적

## 2. MuJoCo의 한계 (공식 문서 근거)

1. **유체 역학은 MuJoCo의 범위 밖**
   > "Proper simulation of fluid dynamics is beyond the scope of MuJoCo"

   — [Computation › Fluid forces](https://mujoco.readthedocs.io/en/stable/computation/fluid.html)

2. **내장 유체 모델은 정지한 균일한 유체만 다룸**
   - 전체 밀도·점성·바람 벡터 하나만 설정 (`<option density viscosity wind>`)
   - 문서 표현: "inviscid, incompressible quiescent fluid"
   - 수면, 파도, 잠긴 깊이에 따른 부력은 계산하지 않음 (문서의 힘 식에 부력 항 없음)
   - → 이 프로젝트처럼 부력·파도를 Python으로 직접 넣는 방식이 MuJoCo에서는 사실상 표준

3. **부가질량은 ellipsoid 모델(`fluidshape="ellipsoid"`)에만 있음**
   - 이 모델은 물체가 유체에 완전히 잠겨 있다고 봄 → 반쯤 잠긴 배에는 맞지 않음
   - 문서: "the added mass term cannot be scaled" (크기 조절 불가)

4. **줄은 flex(케이블)로 만들 수 있지만 조건이 있음**
   - flex 탄성은 적분기가 `discrete`여야 하며, `implicit`/`implicitfast`에서는 오류가 남
   - 이 프로젝트는 `implicitfast` 사용 중 → 적분기를 바꿔야 하고 계산도 느려짐
   - 문서: 큰 flex는 "inefficient both in terms of modeling and in terms of simulation"

   — [Modeling › Deformable objects](https://mujoco.readthedocs.io/en/stable/modeling.html)

5. **접촉은 설계상 "부드러운 접촉"**
   - 물체끼리 살짝 파고들거나 미끄러질 수 있음 ("soft constraints")
   - 이 프로젝트에서는 사람과 배가 부딪히는 경우 정도에만 영향

   — [Modeling › Solver parameters](https://mujoco.readthedocs.io/en/stable/modeling.html)

## 3. 개선 가능성

| 개선 항목 | MuJoCo 안에서 가능? | 방법 |
| --- | --- | --- |
| ✅ 프로펠러가 물 밖에 나오면 추력 끊기 (구현함) | ✅ 쉬움 | 프로펠러 깊이를 파도 높이와 비교해서 추력 줄이기 |
| ✅ 속도에 따른 추력 감소 (구현함) | ✅ 쉬움 | 추력 = 최대 × (1 − 속도/최고속도) 같은 식 |
| ✅ 부가질량 (구현함) | ✅ 중간 | 평판 공식으로 계수 계산 → 관절 `armature`로 넣음 |
| 줄 처짐·질량 | ⚠️ 가능하지만 대가 큼 | flex 케이블. 적분기 변경 필요, 계산 느려짐 |
| ✅ 센서를 실제처럼 (구현함, 열화상은 시야선 방식) | ✅ 중간 | `mj_ray`로 소나 빔 쏘기, 카메라 렌더링으로 열화상 흉내 |
| ✅ IMU 잡음 (구현함) | ✅ 쉬움 | ⚠️ MuJoCo 3.17은 센서 `noise` 속성을 **적용하지 않음** (값만 저장, 직접 확인함) → 파이썬에서 더함 |
| 회절·방사·항적 | ❌ 불가 | 외부 도구로 계수를 미리 계산해서 넣는 방식만 가능 |
| 부서지는 파도·물보라 | ❌ 불가 | 전용 유체 시뮬레이터 필요 |

참고할 만한 외부 도구 (이름만 정리, 쓰기 전에 현재 상태 확인 필요):

- **Capytaine**: 부가질량·방사·회절 계수를 계산하는 오픈소스 도구
- **Stonefish**, **Gazebo 해양 확장**: 해양 로봇 전용 시뮬레이터

## 4. 추천 개선 순서

1. **프로펠러 물 밖 추력 끊기 + 속도에 따른 추력 감소** — 쉽고, 파도 속 견인 결과에 바로 영향
2. **부가질량** — 견인 시작 순간의 줄 힘이 현실에 가까워짐 (이 프로젝트의 핵심 지표가 줄 힘)
3. **IMU 잡음** — MuJoCo가 noise를 적용하지 않아 파이썬에서 더함
4. **줄을 flex 케이블로** — 속도·안정성 문제가 있어 위 세 가지 다음에
