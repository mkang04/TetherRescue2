# Core Logic

TetherRescue AirwayTow 시뮬레이션이 **어떻게 돌아가는지** 핵심만 정리한 문서입니다.
숫자는 모두 기본값이며 [`config/tow_default.yaml`](../config/tow_default.yaml)에서 바꿉니다.

---

## Big Picture

```
좌표 받기 → GPS로 이동 → 센서로 직접 감지 → 접근 → 튜브 건네기 → 사람이 끼움(줄 연결) → 기지로 견인
```

- **MuJoCo**는 몸의 움직임과 충돌만 계산합니다.
- **물(부력·저항)과 줄 힘**은 파이썬이 계산해서 매 순간 몸에 힘으로 넣어 줍니다.
- 박자는 두 개입니다.

| 박자 | 빠르기 | 하는 일 |
| --- | --- | --- |
| 물리 | 250 Hz | 부력·저항·줄·추진력 계산 후 한 걸음 |
| 조종·기록 | 50 Hz | 로봇 두뇌 판단, PID 조종, 기록 한 줄 |

> 화면에 보이는 모양(구조정, 팔다리, 튜브)은 질량 0·충돌 없음입니다.
> 물리는 **상자(로봇·몸통) + 공(머리)** 으로만 계산합니다.

## Ocean & Buoyancy

**파도**: 높이·주기·방향이 조금씩 다른 사인파 8개를 겹칩니다. 같은 시드 = 같은 파도.

**부력·저항**: 몸을 작은 블록으로 나눠서 블록마다 따로 계산합니다.

- 부력: 물에 잠긴 블록 부피만큼 위로 밉니다.
- 저항: 물에 대한 상대 속도로 `선형 + 2차` 저항 (앞뒤·좌우·위아래 계수 따로).

블록마다 힘이 걸리기 때문에, 기울어지면 **저절로 다시 서려는 힘**이 생깁니다.

**부가질량** ([added_mass.py](../tether_rescue/ocean/added_mass.py)): 물속 물체는 주변 물까지 밀어야 해서 더 무겁게 움직입니다.

- 계수는 평판 부가질량 공식(strip theory)으로 선체 크기에서 계산: 로봇 위아래 약 200 kg, 사람 위아래 약 87 kg 등.
- MuJoCo 관절의 `armature`(관성 추가)로 넣어서 안정적으로 계산됩니다. 파도에 들려 덜 잠기면 그만큼 줄어듭니다.
- 파도로 물이 가속하면 그만큼 몸도 끌려갑니다.
- `ocean.added_mass_scale`로 세기를 조절 (0 = 끔).

## Tether

```
줄 힘 T = k × (늘어난 길이) + c × (늘어나는 속도)      (T ≥ 0)
```

| 상태 | 결과 |
| --- | --- |
| 거리 ≤ 3 m (느슨함) | 힘 0 |
| 거리 > 3 m (팽팽함) | 고무줄처럼 당김 (k = 600 N/m) |
| 294 N을 0.05초 넘게 넘음 | **끊어짐** (실패) |

- 줄 힘은 **선미 견인점 ↔ 사람 가슴 견인점** 사이로 계산합니다.
- 튜브를 끼울 때 이미 3 m보다 멀면, 그만큼 줄을 풀어 둔 채 연결하고 **0.2 m/s로 감아 들입니다**.
  (연결하자마자 확 당겨져 끊어지는 것 방지)

## Propulsion & PID

**엔진**

- `throttle` = 최대 추진력(300 N) 대비 비율. 앞으로 100%, 뒤로 30%까지.
- 실제 엔진 세기는 명령을 **0.4초 늦게** 따라갑니다 (MuJoCo 구동기 `thrust`).
- 방향은 선외기가 세로축으로 돌아서 바꿉니다 (조향 서보 `steer`, 최대 0.6 rad).
- **실제 추력 = 엔진 세기 × 프로펠러 효율**
  - 프로펠러가 파도 위로 드러나면 드러난 만큼 줄어듭니다 (헛돎).
  - 빨리 달릴수록 줄어듭니다: `T = T0 × (1 − u / 5 m/s)` (u = 프로펠러가 물을 지나가는 속도).

**IMU 잡음**: MuJoCo는 센서 `noise` 속성을 적용하지 않아서 파이썬에서 더합니다 (MPU-6050 데이터시트 잡음 밀도 + 자이로 고정 오차).

**PID 두 개**

| PID | 입력 | 출력 |
| --- | --- | --- |
| 속도 | 목표 속도 − 현재 속도 | `throttle` |
| 방향 | 목표 방향 − 현재 방향 | `rudder` |

- 견인 목표 속도는 6초에 걸쳐 천천히 올립니다 (출발할 때 줄이 확 당겨지는 것 방지).
- 뒤로 밀 때는 꺾는 방향이 반대로 작용하므로 `rudder` 부호를 뒤집습니다 (구조 임무).

## Airway Check

사람 얼굴이 물 밖에 있는지가 **가장 중요한 성적**입니다.

```
입 높이  <  물 높이 + 선수파 상승   →  얼굴 잠김
선수파 상승 = 0.6 × v² / 2g          (v = 사람이 물을 가르는 속도)
```

빨리 끌수록 머리 앞에 물이 쌓여서 잠기기 쉽습니다. `0.6`은 **검증이 필요한 임시값**입니다.

## Rescue Mission

### Phases

| 단계 | 하는 일 | 다음 단계로 |
| --- | --- | --- |
| `WAIT_GOAL` | 목표 좌표 기다림 | 지도 클릭 / rviz2 / 자동 신고 |
| `TRANSIT` | GPS로 좌표까지 이동 (1.5 m/s) | 4 m 안에 도착 → `SEARCH` |
| `SEARCH` | 사각 나선으로 돌며 탐색 | 사람 '확인' → `APPROACH` (90초 넘으면 실패) |
| `APPROACH` | 감지한 위치로 접근, 3 m 앞에서 멈춤 | 멈추면 → `HANDOFF` |
| `HANDOFF` | 튜브 건네기 ([아래](#tube-handoff)) | 사람이 끼움 → `TOW` |
| `TOW` | 기지로 견인 | 사람이 기지 5 m 안 → **성공** |

접근·건네기 중에 사람을 놓치면 (사람이 튜브를 잡기 전이라면) `SEARCH`로 돌아갑니다.

### Two-Stage Guidance

| 거리 | 쓰는 정보 | 특징 |
| --- | --- | --- |
| 멀리서 | GPS | 오차 약 2.5 m, 수십 초에 걸쳐 천천히 흘러감 |
| 가까이서 | 열화상 + 소나 | **로봇 기준 상대 위치**라 GPS 오차와 상관없음 |

| 센서 | 알려 주는 것 | 약점 |
| --- | --- | --- |
| 열화상 (뱃머리) | 머리 **방향만** | 머리가 잠기면 안 보임. 카메라 ~ 머리 사이를 **파도가 실제로 가리면** 안 보임. 멀수록 놓침 |
| 소나 (물속) | 몸통 거리 + 방향 | MuJoCo 광선(`mj_ray`)으로 **빔 183개**를 쏴서 몸에 맞은 빔으로 판정. 거리는 몸의 **가까운 끝**까지. 파도가 높을수록 **가짜 탐지** |

**추적기**가 가짜를 거릅니다. 아래 둘 중 하나면 '확인'입니다.

- 소나 탐지 3번이 3 m 안에서 겹침 (가짜는 매번 다른 곳에 생김)
- 열화상 방향과 소나 방향이 6° 안으로 맞음

확인한 뒤에도 열화상 방향과 맞는 소나 탐지가 오면 그 거리로 바로잡습니다. 열화상은 방향만 알려 주기 때문에, 처음 거리가 가짜 반사였다면 이렇게 고치지 않는 한 틀린 거리가 그대로 남습니다.

> 로봇 두뇌는 **실제 사람 위치를 모릅니다.** GPS·나침반·속도·센서 탐지만 씁니다.

## Tube Handoff

로봇이 튜브를 씌워 주지 않습니다. **손 닿는 곳에 건네주고, 사람이 직접 잡아서 끼웁니다.**

```
DECK ──▶ OFFERED ──▶ GRABBING ──▶ DONNING ──▶ WORN
갑판 위   줄에 매달아    팔을 뻗어     가슴으로      줄 연결
         띄워 보냄      잡음 (1.2초)  끌어와 끼움 (3초)
```

**사람이 잡는 조건** (시뮬레이터가 실제 어깨 위치로 판정)

- 튜브 고리가 어깨에서 **0.7 m(팔 길이) 안**
- 로봇이 0.6 m/s보다 느림
- 위 상태가 **0.8초** 계속됨 (알아채고 반응하는 시간)

잡는 도중 튜브가 멀어지면 놓치고 `OFFERED`로 돌아갑니다.

**로봇이 하는 일**

| 상황 | 행동 |
| --- | --- |
| 건네는 중 | 사람 앞 3 m를 유지 (가까워지면 뒤로 물러남). 튜브는 뱃머리 앞 0.9 m에 띄움 |
| 2초 지나도 못 잡음 | 배는 그대로, 줄을 풀어 튜브를 사람 쪽으로 보냄 (0.2 m/s, 최대 3.6 m) |
| 20초 지나도 못 잡음 | 위치 추정이 틀린 것 → 튜브 회수, 다시 탐색 |
| 사람이 잡음 | 그 자리에서 기다림 |
| 다 끼움 | 줄 연결 → `TOW` |

**사람이 배에 매달리는 실패** ([boarding.py](../tether_rescue/mission/boarding.py))

공황 상태의 익수자는 손에 닿는 물체에 매달리고 올라타려 합니다. 그래서 배는 다가가지 않고 튜브만 보냅니다.

```
CALM ──(어깨 ~ 선체 1.5 m 안, 1초)──▶ LUNGING ──(손이 뱃전에 닿음 0.7 m)──▶ CLINGING ──(3초)──▶ 실패
평온                                  배로 달려듦 (60 N)                       매달림
         ◀──(배가 물러나 1.8 m 밖)──
```

- 튜브를 **먼저 잡은** 사람은 배에 달려들지 않습니다. 달려들기 시작하면 튜브는 무시합니다.
- 매달리면 뱃전을 체중의 40%로 아래로 누르고 팔 길이로 붙잡습니다. 이 힘 때문에 **배가 뒤집히는 경우가 많습니다** (그러면 '로봇 뒤집힘' 실패).
- 거리는 사람의 가까운 어깨 ~ 선체 상자의 가장 가까운 점입니다. 시뮬레이터가 실제 위치로 판정하며, 로봇 두뇌는 모릅니다.

## Outcomes & Score

> 자세한 내용(판정 순서, 설정 키, 알아둘 점)은 [OUTCOMES.md](OUTCOMES.md)에 있습니다.

| 결과 | 조건 |
| --- | --- |
| 성공 | 끌고 오기: 사람이 50 m 이동 / 구조 임무: 사람이 기지 5 m 안 |
| 줄 끊어짐 | 294 N을 0.05초 넘게 넘음 |
| 로봇 뒤집힘 | 60° 넘게 기욺 |
| 못 찾음 | 탐색 90초 안에 확인 못 함 |
| 사람이 로봇에 매달림 | 튜브 없는 사람이 배에 3초 매달림 |
| 시간 초과 | 끌고 오기 120초 / 구조 임무 300초 |

**종합 점수 (임시 공식, 끌고 오기)**

```
점수 = 간 거리 비율 × (70 × 얼굴 밖 비율 + 30 × min(1, 평균 속도 / 2 m/s))
```

줄 끊김·뒤집힘은 0점입니다.
